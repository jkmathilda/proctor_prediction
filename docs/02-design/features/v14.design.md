## 1. Resolving the Plan's Open Questions

### 1.1 Feature set / imputation source (Plan §6)

**Decision: reuse `helper_functions.py`'s fold-isolated pipeline** (`add_gradation_parameters` →
`prepare_features` → missing-indicator flags → `get_default_mice_imputer` → `apply_fold_feature_engineering`),
the same sequence v6/v7/v10/v13 already use — not the notebook's drop-the-column approach.

**Why this needs to be stated explicitly**: the plan's §3–4 R² numbers (Linear 0.744/0.302, Ridge 0.735/0.388,
XGBoost 0.835/0.797) were computed in `data_analysis.ipynb` on `params_av`, which **drops**
`hyd_cond_kf_m_s`, `hyd_cond_hyd_gradient`, `atterberg_liquid_limit_pct`, `atterberg_plastic_limit_pct`,
`loss_on_ignition_pct`, and `feat_pi` entirely rather than imputing them. That's a third, distinct
preprocessing option the plan hadn't separated out from "MICE" vs. "median-impute" — and it means **v14's
actual Stage 1/2 R²/NMAE numbers will not exactly match the plan's cited figures**, since v14 keeps and
imputes those columns instead of dropping them. Re-measure, don't assume the plan's numbers transfer
directly — they're motivation for the architecture, not a target to reproduce exactly.

Chosen anyway over the notebook's approach because: (a) it's the established, validated pattern across
v5–v13, (b) Atterberg limits carry near-zero SHAP importance per v2 (`model_description.md`) so imputing
vs. dropping them is low-stakes either way, and (c) dropping `hyd_cond_*`/LOI would throw away signal
Stage 2 (XGBoost) may still find in interaction with other features, even if individually weak.

### 1.2 `scripts/model1.py` disposition (Plan §7)

**Decision: `v14.py` supersedes `model1.py`.** Once `v14.py` is implemented and passes its acceptance
criteria, delete `scripts/model1.py` (Do-phase action, not this document) — every other script in
`scripts/` follows the `vN.py` convention and `model1.py` is currently an unimplemented, untracked stub of
the same design under a different name.

### 1.3 What "self-contained, no dependency on v1–v12" (from `model1.py`'s docstring) actually means

Interpreted as: **no dependency on the versioned experiment scripts** (`v1.ipynb`…`v13.py`) or their
results — not a ban on reusing `helper_functions.py`, which is the organizers'-provided shared utility
module, already the common substrate for v5–v13. `v14.py` reuses `helper_functions.py` freely but does
**not** `import` any `scripts/vN.py` file. The one function worth reusing from `scripts/v7.py`
(`soil_composition_strata`, §3.3 below) is small enough (~10 lines) to inline directly into `v14.py` rather
than import, keeping the file genuinely standalone.

## 3. Pipeline Specification

### 3.1 Preprocessing (fold-isolated, shared by all three stages)

```
1. add_gradation_parameters(df)        # psd_C_U, psd_C_C
2. prepare_features(df)                 # psd_fraction_clay/silt/sand/gravel, log_diff_psd_size_at_d*_mm
3. add fine_grained = (psd_fraction_clay + psd_fraction_silt) > 12   # deterministic, no leakage — see note below
4. per fold: set *_is_missing indicators (atterberg, kf, loi) on X_tr and X_va separately
5. imputer = get_default_mice_imputer(seed=seed); fit_transform(X_tr), transform(X_va)   # fold-isolated
6. apply_fold_feature_engineering(X_tr); apply_fold_feature_engineering(X_va)  # log10_kf, PI, skempton, hazen/casagrande interactions
```

Steps 1–3 are deterministic (no fitted state) and safe to compute once before the CV loop, matching
v6/v7's existing pattern. Steps 4–6 must stay inside the fold loop (MICE has fitted state).

**`fine_grained` units**: `psd_fraction_clay`/`psd_fraction_silt` are DIN percentages (0–100), not
0–1 fractions — despite the name — because `prepare_features` sets `psd_fraction_clay =
psd_passing_at_0_002mm_pct` directly, and that raw column is itself a percentage (e.g. `0.68`, `4.27` in
`train.csv`). So the `> 12` threshold is correct as a percent comparison. This is not a new decision —
it's `scripts/v7.py`'s `add_fine_grained_flag` (`v7.py:131-135`), reused verbatim, not reinvented.

### 3.2 Stage 1 — Ridge (global, linear)

- `sklearn.linear_model.Ridge`, one model per target, wrapped with a scaler.
- **Scaling — full sequence** (§3.2 previously named only the last two calls; the complete, runnable
  sequence, matching `scripts/v7.py:214-222`'s precedent exactly):
  1. **Once, pre-CV** (deciding scaler *group membership* only, not fitted scaler state — the same
     accepted mild leak v7 already uses): full-data impute via `H.impute_missing_values(X_base,
     cols_for_imputation, target_cols=[], seed=seed)` → `H.apply_fold_feature_engineering(imp_full)` →
     `df_metrics, num_cols = H.run_distribution_diagnostics(imp_full, diag_exclude, [])` →
     `scaler_groups = H.get_scaler_assignments(imp_full, df_metrics, num_cols)`, where `diag_exclude =
     ["id", "atterberg_is_missing", "kf_is_missing", "loi_is_missing"] + [any column that is all 0/1]`
     (targets are already dropped from `X_base` before this point). `scaler_groups` is a fixed
     `(highly_skewed, with_outliers, standard)` column-name tuple reused by every fold.
  2. **Inside the fold loop**: `preprocessor = H.get_column_preprocessor(*scaler_groups)`, then
     `preprocessor.fit_transform(X_tr)` / `preprocessor.transform(X_va)` — the scaler itself is
     fold-isolated even though which-columns-go-in-which-group was decided once globally.
  - **Headless-run note**: `run_distribution_diagnostics` calls `plt.show()` internally (bar-chart
    diagnostics) — call `matplotlib.use("Agg")` before the `pyplot` import (as `scripts/v10.py`/`v13.py`
    already do) so a non-interactive batch run doesn't block or error.
- **Regularization strength**: sweep `alpha` via `RidgeCV` internally (`alphas=np.logspace(-2, 3, 50)`,
  inner `cv=5` on the training fold only) rather than hand-picking one value — matches
  `data_analysis.ipynb`'s own Ridge cell (`RidgeCV(alphas=np.logspace(-4,4,100), cv=5)`), just narrowed
  slightly since v14's feature set (imputed, not dropped) has fewer extreme-scale columns to cover.
- Output: `linear_pred_mdd`, `linear_pred_owc` (train-fold and val-fold).

### 3.3 Cross-validation folds

Reuse `scripts/v7.py`'s `soil_composition_strata()` logic (dominant DIN fraction per sample —
Sand/Gravel/Fine, Clay merged into Fine since train.csv has only 1 clay-dominant row), inlined into
`v14.py` rather than imported (§1.3). `StratifiedKFold(n_splits=5, shuffle=True, random_state=seed)` on
this stratum label. **Required, not optional** — Plan §3 traced the notebook's catastrophic OWC fold
(R² = −1.45) to exactly the plain-`KFold` fold-composition issue this fixes, and Stage 1 (linear) is the
stage most exposed to it.

### 3.4 Stage 2 — XGBoost on Stage 1 residuals

- Targets: `resid_mdd = y_mdd - linear_pred_mdd`, `resid_owc = y_owc - linear_pred_owc` (fold-isolated:
  residuals computed from the fold's own Stage-1 fit, never leaking val-fold residuals into training).
- `XGBRegressor`, one model per target, starting hyperparameters (heavier-regularized than v1's tuned
  XGBoost, per Plan §6's rationale that residual SNR is lower than direct-target SNR):

  | Param | v1 tuned (direct target) | v14 Stage 2 starting point (residual target) |
  |---|---|---|
  | `max_depth` | 4–6 (Optuna range) | **3** (fixed, not swept) |
  | `learning_rate` | ~0.05–0.1 | **0.02** |
  | `min_child_weight` | 1–5 | **8** |
  | `reg_lambda` | 1–5 | **5.0** |
  | `subsample` / `colsample_bytree` | tuned | **0.7** / **0.7** |
  | `n_estimators` | tuned | **400**, with early stopping on the val fold |

  These are starting points, not a mandated final grid — a light sweep (small manual grid or a handful of
  Optuna trials, reusing the project's existing dependency) over `learning_rate`/`min_child_weight`/`reg_lambda`
  is fine, but should stay narrower than v1's search given the smaller effective sample size after Stage 1
  removes variance.
- Prediction: `stage12_pred = linear_pred + gbm_resid_pred`.

### 3.5 Stage 3 — fine/coarse correction

- Split fold's residuals `r = y - stage12_pred` by `fine_grained` (bool).
- **Default form: per-group additive bias only** — `correction[group] = mean(r[group])` computed on the
  training fold, applied to matching val-fold rows. This is the lowest-capacity option and the one
  `model1.py`'s own docstring flags as the safer default given small group sizes.
- **Group-size gate (Plan §5, now resolved)**: compute the actual `fine_grained` split size on `train.csv`
  before deciding whether a 2-parameter escalation is worth trying. If either group falls below ~30 rows,
  stay with bias-only — a second parameter isn't reliably fittable below that.
  - **`scale` escalation, precisely defined** (fixes an ambiguity: `r` is the quantity being predicted, so
    it cannot also be the regressor): within each group, fit `r ≈ a * stage12_pred + b` by ordinary least
    squares on the **training fold's** `(stage12_pred, r)` pairs — i.e. does the Stage-1+2 model
    systematically over/under-predict more at higher predicted values, within this soil-composition group?
    At inference, apply `correction = a * stage12_pred + b` to the **val fold's** `stage12_pred` for that
    group. Falls back to bias-only (`a=0`, `b=mean(r)`) if `--stage3 scale` is requested but a group is
    below the ~30-row floor.
- Prediction: `final_pred = stage12_pred + group_correction`.

### 3.6 Physical constraint

Reuse `helper_functions.calc_satline(w, Gs)` for the zero-air-voids clip (`mdd = min(final_pred_mdd,
calc_satline(final_pred_owc, rho_s) * 0.999)`) — already validated equivalent to a hand-rolled ZAV formula
since v5; `model1.py`'s docstring-stated "own zav_density implementation" is unnecessary duplication.

### 3.7 Metric

Reuse `helper_functions.calculate_nmae` directly rather than reimplementing — it's already the exact
competition metric (IQR-normalized MAE, macro-averaged over targets).

## 4. Ablation Evaluation Harness

Per fold, compute and store OOF predictions for all three stages (not just the final one):

| Stage | Prediction |
|---|---|
| Stage 1 alone | `linear_pred` |
| Stage 1+2 | `linear_pred + gbm_resid_pred` |
| Stage 1+2+3 (final) | `linear_pred + gbm_resid_pred + group_correction`, saturation-clipped |

Aggregate NMAE for each stage across the **fixed global IQR** (computed once from all training targets,
not recomputed per fold) — v7 already found and documented a bug in `v6.py` where per-fold IQR inflates/
deflates individual fold scores; `v14.py` must not repeat it.

**Reporting**: log all three stage NMAEs plus the final NMAE next to v5's 0.2410–0.2420 for project-level
context (Plan §6) — the ablation is the internal gate, the v5 comparison is external framing, both are
useful and neither replaces the other.

## 5. File / CLI Structure

Mirror `scripts/v6.py`/`v7.py`'s argparse style (not v10/v13's, per §2):

```
python scripts/v14.py --data_dir ./data --out ./submissions/submission_YYYYMMDD_v14.csv
```

| Arg | Default | Purpose |
|---|---|---|
| `--data_dir` | `./data` | train.csv/test.csv location |
| `--out` | `./submissions/submission_v14.csv` | final predictions |
| `--folds` | 5 | stratified k-fold count |
| `--seed` | 42 | reproducibility |
| `--stage3` | `bias` | `bias` (default) or `scale` (escalation, gated by §3.5) |
| `--log` | `v14_run.log` | run log, mirrors v13's `setup_logger` pattern |
